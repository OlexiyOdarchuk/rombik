# Розділення відповідальностей

Чому ядро однаково працює у вебі, CLI та Node — і де проходять межі.

## Правило залежностей

> Залежності спрямовані **всередину**, до чистих моделей. Зовнішнє (DOM, ОС, мова,
> формат виводу) знає про ядро; ядро не знає про зовнішнє.

```
   adapters ──────────► core ◄────────── adapters
 parser/treesitter                       render/svg
 tools/rombik.mjs       ir, layout,       web/ (SvelteKit)
 web/ (SvelteKit)        diagram           (DOM-glue, PNG/PDF)
                          astjson
```

## Хто чого НЕ знає

| Модуль | DOM/ОС? | Знає про мову (Python/C++)? | Знає про формат виводу? |
|--------|:---:|:---:|:---:|
| `ir` | ні | ні | ні |
| `diagram` | ні | ні | ні |
| `layout/` | ні | ні | ні |
| `astjson` | ні | ні* | ні |
| `render/svg` | ні | ні | **так** (SVG) |
| `parser/treesitter` | ні** | **так** | ні |

\* `astjson` знає лише про абстрактний AST-JSON, не про синтаксис мови.
\** сам парсер — чистий TS над структурно-сумісним інтерфейсом `TSNode`; завантаження
WASM-граматик роблять адаптери (CLI/веб), а не модуль.

## Чому це дає браузерний рушій «безкоштовно»

Рушій `rombik-engine` — чистий TypeScript без DOM/ОС. У браузері `web/src/lib/engine.js`
лише завантажує tree-sitter (WASM) і кличе ті самі функції рушія:

```js
const tree = parser.parse(code);                  // web-tree-sitter
const results = fromTree(tree, lang, options);    // rombik-engine
for (const { name, diagram } of results) {
    out.push({ name, svg: renderSvg(diagram), diagram });
}
```

Той самий `layoutProgram` + `renderSvg`, що й у CLI (`tools/rombik.mjs`). Ядро не
помічає, де воно виконується. → [[WASM-міст]].

## Чому це дає тестованість

Можна сконструювати IR (`Block`) руками або подати AST-JSON напряму у `fromAst`, і
прогнати `layoutProgram` без tree-sitter. Рендери мають власні тести
(`packages/engine/test/`), плюс golden-парність (`test/golden/`) тримає вивід байт-у-байт.
Кожен шар ізольований.

## Симетрія входу

Те саме розділення працює і на вході: і CLI (`tools/rombik.mjs`), і веб (`web/`)
виконують **той самий** `parser/treesitter.ts` над деревом tree-sitter і видають
**той самий** AST-JSON. Шов — у [[Чому-AST-JSON-як-контракт]].
