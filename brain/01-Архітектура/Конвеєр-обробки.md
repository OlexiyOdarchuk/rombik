# Конвеєр обробки

Повний шлях від тексту коду до виводу (SVG/Typst/Excalidraw, далі PNG/PDF), етап за
етапом. Приклад — `examples/grade.py`.

## 0. Вхід

```python
def grade(score):
    name = input("Ваше ім'я: ")
    if score >= 90:
        print("Відмінно")
    else:
        print("Інакше")
```

## 1. Код → Tree → AST-JSON  ·  `parser/treesitter.ts`

tree-sitter (web-tree-sitter, WASM-граматика Python чи C++) розбирає код у `Tree`
(НЕ виконує код). `parseTree(tree, lang)` обходить дерево і будує спрощений AST-JSON:

```json
[{
  "name": "grade",
  "block": {"kind":"block","stmts":[
    {"kind":"io","text":"Ввід score"},          // ← параметр функції
    {"kind":"io","text":"Ввід name"},           // ← input(...)
    {"kind":"if","cond":"score >= 90",
     "then":{"kind":"block","stmts":[{"kind":"io","text":"Вивід «Відмінно»"}]},
     "else":{"kind":"block","stmts":[{"kind":"io","text":"Вивід «Інакше»"}]}}
  ]}
}]
```

Деталі трансформацій — [[Парсер-Python]] і [[Підтримувані-конструкції-Python]].

> [!note] Один фронтенд на дві мови
> Той самий `parser/treesitter.ts` обробляє і Python, і C++ (`lang: 'python'|'cpp'`):
> tree-sitter уміє обидві граматики, а зведення в AST-JSON — спільне.

## 2. AST-JSON → IR  ·  `astjson.ts`

`fromJson(astJSON)` десеріалізує JSON у проміжні `AstNode` і зводить їх у
[[IR-проміжне-представлення|ir]]:

```ts
{ name: 'grade', body: { kind: 'block', stmts: [
  { kind: 'io', text: 'Ввід score' },
  { kind: 'io', text: 'Ввід name' },
  { kind: 'if', cond: 'score >= 90', then: {…}, else: {…} },
]}}
```

Вкладені `block`-вузли інлайняться (`toBlock`). IR — чисте дерево, **без жодних
координат**.

## 3. IR → Diagram  ·  `layout/`

`layoutProgram(block, opts)`:

1. **`blockSize`/`measure`** — знизу вгору рахує габарити всього піддерева (скільки
   місця треба). → [[Розкладка-рекурсією-size-і-place]].
2. Ставить термінатор «Початок», ребро вниз.
3. **`place`** — згори вниз роздає координати кожному вузлу, додаючи `Shape` і `Edge`.
4. Збирає всі виходи в `ends` і зводить у «Кінець». → [[Зведення-виходів-у-Кінець]].

Результат — `Diagram { shapes, edges, w, h }` ([[Diagram-модель-геометрії]]).
Оркестрація `build.ts` ще дописує підпис: `caption` = ім'я функції, `figNum` = номер «Рисунок N».

## 4. Diagram → вихід (кілька бекендів)

Один `Diagram` читають **незалежні** рендери:

| Формат | Рендер | Залежності |
|--------|--------|------------|
| `.svg` | `renderSvg(d)` — ребра, тоді ДСТУ-полігони, текст по центру | чистий TS. → [[SVG-рендерер]] |
| `.typ` | `renderTypst(d)` — код Typst/CeTZ | чистий TS. → [[Typst-рендер]] |
| `.excalidraw` | `renderExcalidraw(d)` — формат Excalidraw | чистий TS (JSON) |
| `.json` | серіалізація `Diagram` — сира геометрія | — |
| `.png` / `.pdf` | SVG → `<canvas>` (+ jsPDF) | браузер (`web/src/lib/engine.js`) |

**Жодного зовнішнього бінарника.** PNG/PDF — НЕ у рушії, а у браузерному
`web/src/lib/engine.js`: SVG малюється на `<canvas>`, PDF збирається посторінково через jsPDF.

## Хто на якому етапі

| Етап | CLI (`tools/rombik.mjs`) | Браузер (`web/`) |
|------|--------------------------|------------------|
| Код → Tree | web-tree-sitter (Node) | web-tree-sitter (WASM) |
| Tree → AST-JSON → IR → Diagram | `rombik-engine` | `rombik-engine` |
| SVG/Typst/Excalidraw | `renderSvg/Typst/Excalidraw` | ті самі функції рушія |
| PNG/PDF | — (через SVG зовнішніми засобами) | `engine.js` (canvas + jsPDF) |
| Вивід | файл `.svg/.typ/.json/.excalidraw` (або stdin/stdout-пайпи) | рядок/base64 у JS → DOM/завантаження |

Ядро (кроки 2–4) **байт-у-байт те саме** скрізь — у цьому й суть
[[Розділення-відповідальностей|розділення]]. Golden-тести (`packages/engine/test/golden/`)
тримають цю парність байт-у-байт. → [[WASM-міст]].
