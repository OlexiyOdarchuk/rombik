# Архітектура — огляд

rombik побудований як **конвеєр компілятора**: фронтенд (парсер) → проміжне
представлення → бекенд (рендер). Кожен крок — окремий TS-модуль рушія
`@rombik/engine` з єдиною відповідальністю та мінімумом залежностей.

Репозиторій — npm-монорепо (workspaces): `packages/engine` (рушій, чистий TS, без
DOM/ОС) + `web` (SvelteKit-фронтенд). Ще: `tools/rombik.mjs` (CLI), `examples/`, `brain/`.

## Модулі й залежності

```
   tools/rombik.mjs (CLI) ─┐
   web/ (SvelteKit)        ─┤  адаптери входу/виходу
                           │
   tree-sitter ──► AST-JSON ──► astjson ──► ir
   (web-tree-sitter,  (treesitter.ts)  (fromJson)   │
    Python/C++ WASM)                                ▼
                                          layout ──► diagram ──┬─► render/svg
                                          (layoutProgram)      ├─► render/typst
                                                │              └─► render/excalidraw
                                                └─ measure + place
```

Стрілки — напрям залежності (хто кого імпортує). Ключове:

- **`ir.ts`, `diagram.ts` — листя.** Майже ні від чого не залежать. Чисті моделі
  даних. → [[IR-проміжне-представлення]], [[Diagram-модель-геометрії]].
- **`layout/` залежить лише від `ir`, `diagram`, опцій.** Не знає ні про мову, ні про
  формат виводу, ні про DOM/ОС. → [[Layout-рушій-розкладки]].
- **Три рендери, кожен залежить лише від `diagram`.** `render/svg.ts`,
  `render/typst.ts`, `render/excalidraw.ts` — усі чистий TS. → [[SVG-рендерер]],
  [[Typst-рендер]], [[Растровий-рендер-PNG-PDF]].
- **`astjson.ts` залежить лише від `ir`.** Спільний для всіх мов/середовищ.
- **`parser/treesitter.ts` — єдиний фронтенд парсера.** Бере Tree від tree-sitter і
  зводить у AST-JSON; обидві мови. → [[Розділення-відповідальностей]].
- **`build.ts`** — оркестрація (`fromTree`/`fromAst`/`splitFromAst`): склейка
  парсер → layout → підпис. Публічний API — у `index.ts`. → [[Публічний-API-rombik]].

## Ядро vs адаптери

| Шар | Модулі | Властивість |
|-----|--------|-------------|
| **Ядро** | `ir`, `layout/`, `diagram`, `render/{svg,typst,excalidraw}`, `astjson` | Без DOM/ОС/мережі/мови. Однаково у вебі, CLI, Node. |
| **Адаптери входу** | `parser/treesitter` + web-tree-sitter (WASM) | Дають AST-JSON. Залежать від tree-sitter. |
| **Адаптери виводу** | `tools/rombik.mjs` (файли), `web/` (DOM, PNG/PDF) | Серіалізують результат, малюють PNG/PDF з SVG. |
| **Оркестрація** | `build.ts` / `index.ts` | Публічний API рушія. |

Межа між ядром і адаптерами — **AST-JSON на вході** і **Diagram → SVG/Typst/Excalidraw/JSON
на виході**. Усе посередині не знає, звідки прийшли дані й куди підуть. →
[[Чому-AST-JSON-як-контракт]].

## Потік даних

Детально по кроках — у [[Конвеєр-обробки]]. Стисло:

1. **Код → Tree → AST-JSON.** tree-sitter розбирає Python/C++, `parseTree(tree, lang)`
   у `parser/treesitter.ts` зводить у AST-JSON. → [[Парсер-Python]].
2. **AST-JSON → IR.** `fromJson` будує дерево `Func`/`Block`/`Node` (`astjson.ts`).
3. **IR → Diagram.** `layoutProgram` рекурсивно рахує габарити (`measure`) і роздає
   координати (`place`). → [[Розкладка-рекурсією-size-і-place]].
4. **Diagram → вихід.** `renderSvg` (SVG), `renderTypst` (Typst/CeTZ),
   `renderExcalidraw` (Excalidraw), або серіалізація геометрії у JSON. PNG/PDF —
   у браузері з SVG через canvas + jsPDF.

## Чому такі межі

- **Тестованість.** Ядро можна годувати AST-JSON/IR напряму, без tree-sitter.
- **Багатомовність.** Новий фронтенд лише має видати AST-JSON — решта безкоштовна.
  Зараз один парсер (tree-sitter) уже покриває Python і C++. → [[Як-додати-нову-мову]].
- **Без сервера.** Та сама межа дає браузерний рушій без серверного коду й нуль-серверний
  застосунок. → [[Браузерний-рушій]].
