# Зведення виходів у Кінець

Як усі шляхи, що завершують функцію (`return/raise/exit` і природний вихід), доходять
до термінатора «Кінець». І як `break` виходить із циклу. Усе в
`packages/engine/src/layout/place.ts`, клас `Builder`.

## Два режими: single-end vs per-exit

Опція `singleEnd` ([[Опції-рендера]]):

| Режим | Поведінка | Що за ДСТУ |
|-------|-----------|------------|
| **per-exit** (типово) | кожен `return/raise/exit` малює **свій локальний «Кінець»** | допустимо |
| **single-end** (`-single-end`) | усі виходи зводяться в **ОДИН** «Кінець» унизу | теж допустимо |

Обидва режими — за ДСТУ; вибір за смаком викладача.

## placeTerminal — return/raise/exit

```ts
placeTerminal(text: string, cx: number, top: number): [Point, boolean] {
  const kind: Kind = this.o.returnAsIO ? 'io' : 'process'; // прямокутник або паралелограм
  const exit = this.leaf(kind, text, cx, top);
  if (this.o.singleEnd) { this.ends.push(exit); return [exit, true]; } // → у спільний Кінець
  // per-exit: одразу свій локальний «Кінець» під блоком
  const endTop = exit.y + vGap;
  this.d.edges.push(edge(exit, P(cx, endTop)));
  this.d.shapes.push(term(cx, endTop, this.o.endText));
  return [P(cx, endTop + termH), true];
}
```

Повертає `ended=true` — після `return` решта блоку недосяжна
([[Розкладка-рекурсією-size-і-place]]).

## Природний вихід

Якщо тіло функції **не** завершилось `return`'ом, його кінцева точка теж іде в
`this.ends` (у `run`). Тобто `ends` містить усі точки, які треба звести в «Кінець».

## routeEnds — зведення в «Кінець»

```ts
routeEnds(cx: number, kY: number): void {
  if (this.ends.length === 1) {           // один вихід — ребро прямо в Кінець
    // (або «вбік і вниз», якщо точка не на осі cx)
    return;
  }
  // кілька: ліва/права шина збору обабіч (busLeft/busRight), кожен вихід вливається
  // у свою шину (arrowless), шини сходяться в jy, тоді ОДНА стрілка вниз у Кінець
  const [right, left] = this.bodyExtent(0, 0, cx);
  const busRight = right + mergeGap, busLeft = left - mergeGap;
  const jy = kY - vGap;
  // ... для кожного e: до busLeft або busRight залежно від e.x < cx
  this.d.edges.push(edge(P(cx, jy), P(cx, kY)));  // спільна стрілка в Кінець
}
```

- **Дві бічні шини збору** (`busLeft` / `busRight`) обабіч від усього вмісту: вихід
  іде до тієї шини, з якого боку від `cx` він стоїть — щоб лінія збору не різала
  фігури в центрі. Раніше тут був явний A*-обхід; тепер маршрут шинний.
- **Один Кінець, багато входів:** усі вливаються в спільну точку збору `jy` без
  вістрів, а вниз у «Кінець» іде єдина стрілка — щоб не було «букета голів»
  ([[Diagram-модель-геометрії]]).
- Якщо виходів кілька, «Кінець» опускають на `mergeGap` нижче — запас під шину збору,
  щоб вона не різала фігури.

## break — routeBreaks

`break` не має фігури. Точка break реєструється (`recordBreak`) у вершину стека
`loopBreaks` поточного циклу. Після тіла:

```ts
routeBreaks(cx: number, contY: number, pts: Point[]): void {
  pts.forEach((p, i) => {
    if (p.x ≈ cx) { /* прямо вниз до contY */ return; }
    const safeY = contY - (pts.length - 1 - i) * 7; // легке розведення по висоті
    /* p → (p.x, safeY) → (cx, safeY) → (cx, contY) */ // вбік і вниз
  });
}
```

Усі break-и циклу зводяться до `contY` — точки **продовження після циклу**. Стек
`loopBreaks` (і парний `loopConts` для `continue`) забезпечує правильну адресацію у
**вкладених** циклах (стрибок → найближчий цикл). → [[Розкладка-циклів]].

## contentBottom

Де ставити «Кінець» по вертикалі: `contentBottom(d)` шукає найнижчу точку серед усіх
фігур і ребер, `run` додає `vGap` (+`mergeGap` якщо виходів багато). Так «Кінець»
завжди нижче всього вмісту.
