# Глосарій

Терміни проєкту в одному місці.

| Термін | Що означає |
|--------|------------|
| **AST-JSON** | Спрощене дерево синтаксису у JSON — мова-агностик контракт між парсером і ядром. Той самий формат видає Python-парсер у CLI та Pyodide у браузері. → [[Чому-AST-JSON-як-контракт]] |
| **IR** (intermediate representation) | Логічне дерево алгоритму (`pkg/ir`): `Process`, `IO`, `If`, `For`, `Block`… Жодної геометрії. → [[IR-проміжне-представлення]] |
| **Diagram** | Геометричний результат: фігури з координатами + ребра-ламані (`pkg/diagram`). Контракт між layout і render. → [[Diagram-модель-геометрії]] |
| **Shape / Фігура** | Один графічний примітив ДСТУ з типом, (x,y), шириною/висотою і текстом. |
| **Edge / Ребро** | Стрілка як ортогональна ламана (масив точок) з опційним підписом. `Arrowless` — без вістря. |
| **place** | Фаза розкладки, що роздає координати: малює вузол у `(cx, top)`. → [[Розкладка-рекурсією-size-і-place]] |
| **size** | Фаза розкладки, що рахує габарити піддерева ДО розміщення. |
| **cx** | Центральна вертикальна вісь (x). Уся схема симетрична відносно неї. |
| **ended** | Прапорець «гілка завершилась» (`return/raise/exit/break`) — потік далі не йде, решта інструкцій недосяжна. |
| **ends** | Зібрані точки-виходи, що зводяться у термінатор «Кінець». → [[Зведення-виходів-у-Кінець]] |
| **guard** | `if cond: BODY` без `else`: дія прямо вниз, порожня гілка — вбік. → [[Розкладка-if-guard-і-симетрія]] |
| **loop arc / дуга повернення** | Лінія, що веде з низу тіла циклу назад до заголовка (повтор ітерації). |
| **Термінатор** | Овал «Початок»/«Кінець» (ДСТУ). У коді — `diagram.Terminator`. |
| **Підпрограма / Predef** | Виклик функції — прямокутник із боковими рисками. |
| **single-end vs per-exit** | Один спільний «Кінець» проти окремого «Кінця» на кожен `return`. Опція `SingleEnd`. |
| **сітка Ганана** | Сітка з ліній, проведених крізь усі краї перешкод; на ній A* шукає обхідний шлях. → [[A-зірка-маршрутизація]] |
| **Pyodide** | CPython, скомпільований у WASM. У браузері виконує `parser.py`. → [[Браузерний-двигун]] |
| **WASM-міст** | Два модулі: `cmd/wasm` (легкий, SVG/Typst) і `cmd/wasmraster` (важкий, PNG/PDF, lazy). → [[WASM-міст]] |
| **ядро vs адаптери** | Ядро: `ir → layout → diagram → рендери` (без ОС/мови/виводу). Адаптери: `parser/python`, CLI, WASM. → [[Розділення-відповідальностей]] |
| **Typst / CeTZ** | Система верстки Typst та її графічний пакет CeTZ. `render/typst` видає Typst-код, що компілюється у чіткий PDF. → [[Typst-рендер]] |
| **raster** | Пакет `render/raster` — нативний PNG/PDF через `tdewolff/canvas` (вшитий шрифт), без зовнішніх бінарників. → [[Растровий-рендер-PNG-PDF]] |
| **Підпис / «Рисунок N»** | Поля `Caption`/`FigNum`/`CapWord`/`CapFormat` у `Diagram`; рядок будує `CaptionLine()`. → [[Diagram-модель-геометрії]] |
| **фасад (pkg/rombik)** | Високорівневий API `FromPython/FromAST/FromIR` + методи `Result.SVG/Typst/PNG/PDF`. → [[Публічний-API-rombik]] |
| **tdewolff/canvas** | Go-бібліотека векторного малювання (PNG/PDF/SVG); єдина зовнішня залежність модуля — заради нативних PNG/PDF. → [[Растровий-рендер-PNG-PDF]] |
