# Глосарій

Терміни проєкту в одному місці.

| Термін | Що означає |
|--------|------------|
| **AST-JSON** | Спрощене дерево синтаксису у JSON — мова-агностик контракт між парсером і ядром. Той самий формат видає tree-sitter для Python і для C++, для вебу і для Node. → [[Чому-AST-JSON-як-контракт]] |
| **IR** (intermediate representation) | Логічне дерево алгоритму (`packages/engine/src/ir.ts`): `process`, `io`, `if`, `for`, `block`… Дискримінований union за полем `kind`. Жодної геометрії. → [[IR-проміжне-представлення]] |
| **Diagram** | Геометричний результат: фігури з координатами + ребра-ламані (`packages/engine/src/diagram.ts`). Контракт між layout і render. → [[Diagram-модель-геометрії]] |
| **Shape / Фігура** | Один графічний примітив ДСТУ з типом, (x,y), шириною/висотою і текстом. |
| **Edge / Ребро** | Стрілка як ортогональна ламана (масив точок) з опційним підписом. `arrowless` — без вістря. |
| **place** | Фаза розкладки, що роздає координати: малює вузол у `(cx, top)` (`layout/place.ts`). → [[Розкладка-рекурсією-size-і-place]] |
| **size / measure** | Фаза розкладки, що рахує габарити піддерева ДО розміщення (`layout/measure.ts`). |
| **cx** | Центральна вертикальна вісь (x). Уся схема симетрична відносно неї. |
| **ended** | Прапорець «гілка завершилась» (`return/raise/exit/break`) — потік далі не йде, решта інструкцій недосяжна. |
| **ends** | Зібрані точки-виходи, що зводяться у термінатор «Кінець». → [[Зведення-виходів-у-Кінець]] |
| **guard** | `if cond: BODY` без `else`: дія прямо вниз, порожня гілка — вбік. → [[Розкладка-if-guard-і-симетрія]] |
| **loop arc / дуга повернення** | Лінія, що веде з низу тіла циклу назад до заголовка (повтор ітерації). |
| **Конектор / Розбиття схем** | Кружечок із цифрою/літерою, що використовується для розбиття завеликої схеми на частини (`splitByHeight`/`splitFromAst`). |
| **Термінатор** | Овал «Початок»/«Кінець» (ДСТУ). У коді — `kind: 'terminator'`. |
| **Підпрограма / subprogram** | Виклик функції — прямокутник із боковими рисками (`kind: 'subprogram'`). |
| **single-end vs per-exit** | Один спільний «Кінець» проти окремого «Кінця» на кожен `return`. Опція `singleEnd`. |
| **tree-sitter** | Швидкий інкрементний парсер, що компілюється у WASM (web-tree-sitter). Розбирає і Python, і C++; результат зводиться в AST-JSON у `parser/treesitter.ts`. → [[Браузерний-рушій]] |
| **рушій `@rombik/engine`** | Чистий TypeScript-пакет (`packages/engine`) без DOM/ОС: `tree-sitter → AST-JSON → ir → layout → diagram → рендери`. Однаковий у вебі, CLI та Node. → [[Розділення-відповідальностей]] |
| **ядро vs адаптери** | Ядро: `ir → layout → diagram → рендери` (без ОС/мови/виводу). Адаптери: парсер (tree-sitter), CLI (`tools/rombik.mjs`), фронтенд (`web/`). → [[Розділення-відповідальностей]] |
| **Typst / CeTZ** | Система верстки Typst та її графічний пакет CeTZ. `render/typst.ts` видає Typst-код, що компілюється у чіткий PDF. → [[Typst-рендер]] |
| **PNG/PDF** | Растрові формати; будуються у браузері з SVG через `<canvas>` + jsPDF у `web/src/lib/engine.js` — НЕ у рушії. → [[Растровий-рендер-PNG-PDF]] |
| **Підпис / «Рисунок N»** | Поля `caption`/`figNum`/`capWord`/`capFormat` у `Diagram`; рядок будує `captionLine()`. → [[Diagram-модель-геометрії]] |
| **публічний API** | `index.ts` рушія: `fromTree`, `fromAst`, `parseTree`, `splitFromAst`, `renderSvg/renderTypst/renderExcalidraw`, `layoutProgram`. → [[Публічний-API-rombik]] |
| **Excalidraw** | Векторний формат нескінченної дошки, що використовується на клієнті для редагування згенерованих схем (`render/excalidraw.ts`). |
