# Браузерний рушій

Як rombik працює у браузері **повністю локально** — без сервера, без надсилання коду
кудись. Складових дві: **Tree-sitter** (парсер, WASM-граматики) + **`rombik-engine`**
(розкладка й рендер — звичайний TypeScript-модуль, що бандлиться разом із застосунком).

> [!important] Нуль довіри до сервера
> Студентський код нікуди не йде. І розбір (Tree-sitter), і розкладка+рендер
> (`rombik-engine`) відбуваються у вкладці браузера. → [[Задум-і-мотивація]].

## Потік

```
Код (Python/C/C++/Pascal)
   │  web-tree-sitter (WASM-граматика) будує синтаксичне дерево Tree
Tree
   │  parseTree(tree, lang) → AST-JSON; fromAst(ast, options) → схеми
{ functions: [{ name, diagram }] }
   │  renderSvg(diagram) → svg; Svelte вставляє svg у DOM
   │  кнопки SVG / Typst / PNG / PDF / Excalidraw
   │
   ├─ редагування підпису → renderCaption(diagram, cap) → новий svg (без ре-парсингу)
   └─ експорт PNG/PDF → браузерний SVG→canvas (+ jsPDF, лінивий import)
```

- **Tree-sitter** (`web-tree-sitter`) швидко й нативно розбирає Python, C, C++ і Pascal через
  маленькі `.wasm` граматики; `parseTree` зводить дерево до канонічного AST.
  (Раніше для розбору використовувався важкий `Pyodide`.)
- **`rombik-engine`** — чистий TypeScript: `fromTree`/`fromAst` будують
  [[Diagram-модель-геометрії|Diagram]], а `renderSvg`/`renderTypst`/`renderExcalidraw`
  його рендерять. Жодного Go-WASM. → [[WASM-міст]].

Чому межа саме тут — [[Чому-AST-JSON-як-контракт]], [[Розділення-відповідальностей]].

## engine.js — клей

`web/src/lib/engine.js` — тонка обгортка над `rombik-engine` + Tree-sitter.
Експортує (приблизно):

| Функція | Призначення |
|---------|-------------|
| `warmup(onProgress?)` | ідемпотентна ініціалізація: лише Tree-sitter (граматики Python/C/C++/Pascal) |
| `generate(code, options, onProgress?)` | код → `{functions:[{name, svg, diagram}], warning?}` або `{error}` |
| `splitSchema(name, maxH, options)` | розбиває довгу схему на частини через з'єднувачі |
| `renderCaption(diagram, cap)` | дешевий ре-рендер підпису → `{svg, typst}` |
| `renderTypst` / `renderTypstAll` | Typst однієї/усіх схем (можна fragment без преамбули) |
| `renderSvgAll(diagrams)` | один SVG з усіх схем (вертикально) |
| `renderExcalidraw(diagram)` / `All` | формат **Excalidraw** з `diagram` прямо на клієнті |
| `renderPng` / `renderPdf` (`…All`) | браузерний растр: SVG→canvas (+ jsPDF) |

```js
// generate — суть
parser.setLanguage(langs[lang]);
const tree = parser.parse(code);
lastAst = parseTree(tree, lang);
const functions = fromAst(lastAst, options).map((r) => ({
  name: r.name, diagram: r.diagram, svg: renderSvg(r.diagram),
}));
```

`initPromise` гарантує одноразову ініціалізацію Tree-sitter (можна прогріти заздалегідь
через `warmup`). Помилки парсингу відловлюються; за `tree.rootNode.hasError` повертається
`warning` зрозумілою мовою.

## PNG/PDF у браузері

Растеризація — без жодного WASM: `renderSvg` дає SVG, далі `<img>` зі SVG →
`<canvas>` (білий фон) → PNG; PDF — той самий растр посторінково через **jsPDF**
(лінивий `import('jspdf')`). → [[WASM-міст]].

## Артефакти у static/

Граматики Tree-sitter лежать у `web/static/` (`tree-sitter.js`, `tree-sitter.wasm`,
`tree-sitter-python.wasm`, `tree-sitter-cpp.wasm`) і вантажаться напряму під час
`warmup`. **Жодного `rombik.wasm`/`rombik-raster.wasm`/`wasm_exec.js` більше немає** —
рушій бандлиться vite разом із застосунком як TS-джерело. → [[Збірка-і-запуск]].
