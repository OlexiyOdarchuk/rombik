# Як додати нову мову

Завдяки [[Чому-AST-JSON-як-контракт|AST-JSON як контракту]], додати підтримку нової
мови (JavaScript, Pascal…) — це **лише навчити парсер видавати той самий AST-JSON**.
Уся розкладка, рендер і опції — спільні й безкоштовні. Python, C, C++ і Pascal уже працюють через
один файл `parser/treesitter.ts`.

## Підхід rombik: web-tree-sitter

Парсер — `packages/engine/src/parser/treesitter.ts`. Він бере **дерево
web-tree-sitter** (`Tree`) і мову (`'python' | 'cpp'`), а видає масив `AstFunc`. Гілки
для Python, C, C++ і Pascal живуть поруч у тій самій функції `parseTree`; різниця — лише в іменах
вузлів граматики (`if_statement`, `for_statement`, `compound_statement` тощо).

Додати мову — це:

1. **Граматика.** Підключити wasm-граматику tree-sitter (як `tree-sitter-python.wasm`,
   `tree-sitter-cpp.wasm` у `web/static/`). У dev — також у `tools/build-cli.mjs`, щоб
   standalone-CLI ніс її поруч.
2. **Гілка в парсері.** Розширити `Lang` і додати мапінг вузлів нової мови → AST-JSON
   у `parseTree` (за зразком наявних `isPy`/`isCpp` гілок).
3. Усе. **Ядро не чіпається.**

## Контракт виходу

`parseTree` повертає масив `AstFunc` ([[astjson-конвертер]]):

```ts
interface AstFunc { name: string; block: AstNode; }   // block.kind === 'block'
```

Вузли (`kind` + потрібні поля), які розуміє `fromJson`/`toNode`:

| kind | поля | сенс |
|------|------|------|
| `process` | `text` | дія |
| `io` | `text` | ввід/вивід (текст із префіксом «Ввід»/«Вивід») |
| `call` | `text` | виклик підпрограми (функція з цього ж файлу) |
| `terminal` | `text` | return/raise/throw/exit |
| `if` | `cond`, `then`, `else` (вузли-block) | розгалуження |
| `for` | `cond` (= spec «i = a, b, c»), `body`, `else` | цикл-лічильник |
| `while` | `cond`, `body`, `else` | передумова |
| `dowhile` | `cond`, `body` | післяумова |
| `infloop` | `body` | нескінченний |
| `break` | — | вихід циклу |
| `continue` | — | стрибок на заголовок циклу |
| `block` | `stmts` | послідовність (вкладені інлайняться у `toBlock`) |

Невідомі `kind` тихо відкидаються (`toNode` → `null`), тож зайві вузли не ламають
розкладку.

## Куди підключити

- **Рушій/CLI:** усе через `parseTree` → `fromTree`/`fromAst` (`build.ts`). Якщо парсер
  зовнішній і вже видає AST-JSON, клич `fromAst(json, opts)` напряму.
- **Браузер:** граматику в `web/static/`, завантаження у `web/src/lib/engine.js`
  (`Language.load`), решта — той самий рушій. → [[Браузерний-рушій]].

## Що НЕ треба чіпати

- `ir`, `layout`, `diagram`, `render/{svg,typst,excalidraw}` — **нічого**.
- Опції рендера ([[Опції-рендера]]) — працюють однаково.

## Конвенції, які варто повторити

Щоб схема виглядала «курсовою» (як у наявних гілках):

- параметри функції → перший `io` «Ввід …»;
- виклик власної функції → `call`, бібліотечний — ні (потрібен аналог `defined` через
  `collectDefinedFunctions`);
- `for` зі скінченним діапазоном → spec «змінна = початок, кінець, крок»
  (верхня межа — `stop-1`, пор. `endof`);
- довгий текст обрізати (≈64 символи, `oneline`).

Деталі цих рішень — [[Парсер-Python]], [[ДСТУ-19.701-90]].

## Чому це дешево

Межа «AST-JSON» спеціально зроблена мова-агностик і середовище-агностик
([[Розділення-відповідальностей]]). Уся складність (геометрія, ДСТУ, дуги циклів,
зведення в Кінець) живе за цією межею й перевикористовується для будь-якої мови.
