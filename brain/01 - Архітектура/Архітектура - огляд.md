# Архітектура — огляд

rombik побудований як **конвеєр компілятора**: фронтенд (парсер) → проміжне
представлення → бекенд (рендер). Кожен крок — окремий Go-пакет з єдиною
відповідальністю та мінімумом залежностей.

## Пакети й залежності

```
                       ┌──────────────────────────────────────────┐
   cmd/rombik (CLI) ──┤                                          │
   cmd/wasm  (браузер) ┤  адаптери входу/виходу                   │
                       └───────────────┬──────────────────────────┘
                                       │
   parser/python ──► AST-JSON ──► parser/astjson ──► ir
   (python3 + ast)   (рядок)        (FromJSON)        │
                                                      ▼
                                                   layout ──► diagram ──► render/svg
                                                   (Build)              (Render)
                                                      │
                                                      └─ використовує route (A*)
```

Стрілки — напрям залежності (хто кого імпортує). Ключове:

- **`ir`, `diagram` — листя.** Ні від чого не залежать (крім stdlib). Це чисті
  моделі даних. → [[IR - проміжне представлення]], [[Diagram - модель геометрії]].
- **`layout` залежить лише від `ir`, `diagram`, `route`.** Не знає ні про Python,
  ні про SVG, ні про ОС. → [[Layout - рушій розкладки]].
- **`render/svg` залежить лише від `diagram`.** Чистий «адаптер виводу».
- **`parser/astjson` залежить лише від `ir`.** Спільний для всіх мов/середовищ.
- **`parser/python` — єдиний, хто торкається ОС** (`os/exec` → `python3`). Тому його
  **не імпортує** WASM-збірка. → [[Розділення відповідальностей]].

## Ядро vs адаптери

| Шар | Пакети | Властивість |
|-----|--------|-------------|
| **Ядро** | `ir`, `layout`, `diagram`, `render/svg`, `route`, `parser/astjson` | Чистий, без ОС/мережі/мови. Однаково в CLI і WASM. |
| **Адаптери входу** | `parser/python` (CLI), Pyodide (браузер) | Дають AST-JSON. Залежать від середовища. |
| **Адаптери виводу** | `cmd/rombik` (файли), `cmd/wasm` (JS), фронтенд | Серіалізують результат. |

Межа між ядром і адаптерами — **AST-JSON на вході** і **SVG/JSON на виході**. Усе
посередині не знає, звідки прийшли дані й куди підуть. → [[Чому AST-JSON як контракт]].

## Потік даних

Детально по кроках — у [[Конвеєр обробки]]. Стисло:

1. **Код → AST-JSON.** `parser/python` запускає `parser.py` через `python3`
   (у браузері — Pyodide). → [[Парсер Python]].
2. **AST-JSON → IR.** `astjson.FromJSON` будує дерево `ir.Func`/`ir.Block`/`ir.Node`.
3. **IR → Diagram.** `layout.Build` рекурсивно рахує габарити (`size`) і роздає
   координати (`place`). → [[Розкладка рекурсією - size і place]].
4. **Diagram → вихід.** `svg.Render` друкує SVG; або `json.Marshal` віддає геометрію.

## Чому такі межі

- **Тестованість.** Ядро можна годувати IR напряму, без Python.
- **Багатомовність.** Новий фронтенд (C++, JS) лише має видати AST-JSON — решта
  безкоштовна. → [[Як додати нову мову]].
- **WASM.** Та сама межа дозволяє викинути `os/exec` із браузерної збірки і
  отримати нуль-серверний застосунок. → [[Браузерний двигун]].
