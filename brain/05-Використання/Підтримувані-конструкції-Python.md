# Підтримувані конструкції Python

Що `parser.py` ([[Парсер-Python]]) розпізнає, у що зводить і що ігнорує.

## Розпізнається

| Python | Фігура / вузол | Текст / нюанс |
|--------|----------------|---------------|
| `x = expr` | процес | `x = expr` |
| `x += 1`, `x: int = 0` | процес | augmented / annotated теж |
| `x = input(...)` | ввід (паралелограм) | «Ввід x» (`has_input` ловить `input` будь-де) |
| `print(...)` | вивід | «Вивід …»; порожній `print()` → «Вивід порожнього рядка» |
| `if / elif / else` | ромб + гілки | `elif` = вкладений if; будь-яка глибина |
| `match / case` | ромб(и) | **зводиться в ланцюг if** (3.10+); патерни value/singleton/or/as |
| `for i in range(a,b,c)` | шестикутник | «i = a, b-1, c»; кінець = `stop-1` |
| `for x in iter` (не range) | шестикутник | «x ∈ iter» |
| `for … else:` | + гілка else | виконується після нормального завершення (без break) |
| `while cond:` | ромб-передумова + тіло | + `while … else:` |
| `while True: … if C: break` (останнім) | do-while | ромб-післяумова |
| `while True:` (break усередині) | нескінченний цикл | без ромба; вихід лише через break |
| `break` | — (без фігури) | стрибок на вихід циклу |
| `continue` | — (без фігури) | стрибок на заголовок циклу (`ir.Continue`) |
| `return v` | термінал → «Кінець» | «Повернути v» |
| `raise e` | термінал → «Кінець» | «Помилка: e» |
| `exit()`, `quit()`, `sys.exit()` | термінал → «Кінець» | «Вихід» |
| `x = моя_функція(...)` | підпрограма (риски) | лише для функцій, визначених у файлі |
| `with ... as v:` | блок | «відкрити: …» + тіло |
| `try / except` | блок (прозоро) | малюється тіло `try` + `else`; обробку винятків опускаємо |
| `def` (зокрема вкладений) | окрема схема | параметри → вхідний паралелограм |

## Нове проти першої версії

- **`continue`** → `ir.Continue` (раніше ігнорувався). Малюється дугою на заголовок
  циклу. → [[Розкладка-циклів]].
- **`for/else`, `while/else`** → поля `Else` у `ir.For`/`ir.While`: гілка після
  нормального виходу (без break).
- **`match/case`** → лоуериться в ланцюг `if` (окремого ДСТУ-символу для match нема).
- **`try`** тепер явно прозорий (тіло `try`+`else`).

## Ігнорується

`SKIP = (Pass, Import, ImportFrom, FunctionDef, AsyncFunctionDef, ClassDef)` + докстрінги.

| Конструкція | Чому |
|-------------|------|
| `import` / `from … import` | не частина алгоритму |
| `pass` | порожня дія |
| докстрінги | коментар, не дія (`is_docstring`) |
| `class` | методи-дандери — шум; у класи не заходимо |
| вкладені `def` у тілі | ідуть **окремими** схемами |

## Особливі правила

- **Кожна функція — окрема схема.** Код поза функціями → схема `main`.
- **Параметри — ввід:** `def f(a, b)` → перший вузол «Ввід a, b».
- **«Своя» функція vs бібліотечна:** `Call` лише для функцій із `defined`.
- **Обрізання тексту:** один рядок, до 64 символів, далі «…».
- **f-рядки:** `f"сума {x}"` → `сума {x}`.

## Межі

- Обробка конкретних `except`-гілок не малюється (показуємо «щасливий шлях»).
- Comprehension/генератори як керування, декоратори, async-керування — не моделюються.
- Довгі вирази обрізаються до ~64 символів.
