# Підтримувані конструкції Python

Що `parser.py` ([[Парсер-Python]]) розпізнає, у що зводить і що ігнорує. Повна
таблиця відповідностей.

## Розпізнається

| Python | Фігура / вузол | Текст / нюанс |
|--------|----------------|---------------|
| `x = expr` | процес | `x = expr` |
| `x += 1`, `x: int = 0` | процес | augmented / annotated теж |
| `x = input(...)` | ввід (паралелограм) | «Ввід x». `has_input` ловить `input` будь-де у виразі |
| `print(...)` | вивід | «Вивід …»; рядки → «…»; порожній `print()` → «Вивід порожнього рядка» |
| `input(...)` (як вираз) | ввід | «Ввід …» |
| `if / elif / else` | ромб + гілки | `elif` = вкладений if у `else`; будь-яка глибина |
| `for i in range(a,b,c)` | шестикутник | «i = a, b-1, c»; кінець = `stop-1` (range напіввідкритий) |
| `for x in iter` (не range) | шестикутник | «x ∈ iter» |
| `while cond:` | ромб-передумова + тіло | [[Розкладка-циклів]] |
| `while True: … if C: break` (останнім) | do-while | ромб-післяумова; Cond = умова break |
| `while True:` (break усередині) | нескінченний цикл | без ромба; вихід лише через break |
| `break` | — (без фігури) | стрибок на вихід циклу |
| `return v` | термінал → «Кінець» | «Повернути v» (або «Повернути») |
| `raise e` | термінал → «Кінець» | «Помилка: e» (або «Помилка») |
| `exit()`, `quit()`, `sys.exit()` | термінал → «Кінець» | «Вихід» |
| `x = моя_функція(...)` | підпрограма (риски) | лише якщо функція визначена в цьому ж файлі |
| `моя_функція(...)` (як вираз) | підпрограма | те саме |
| `with ... as v:` | блок | «відкрити: …» + тіло |
| `try / except` | блок (прозоро) | малюється тіло `try` + `else`; обробку винятків опускаємо |
| `def` (зокрема вкладений) | окрема схема | кожна функція → свій `Func`; параметри → вхідний паралелограм |

## Ігнорується

`SKIP = (Pass, Import, ImportFrom, FunctionDef, AsyncFunctionDef, ClassDef)` + докстрінги.

| Конструкція | Чому |
|-------------|------|
| `import` / `from … import` | не частина алгоритму |
| `pass` | порожня дія |
| докстрінги (рядок-літерал як вираз) | коментар, не дія (`is_docstring`) |
| `class` | методи-дандери — зайвий шум; у класи парсер не заходить |
| вкладені `def` у тілі | не малюються inline — ідуть **окремими** схемами |

## Особливі правила

- **Кожна функція — окрема схема.** Файл із кількома `def` дає кілька діаграм. Код поза
  функціями → схема `main` (або `програма`, якщо `main` зайнятий).
- **Параметри — ввід.** `def f(a, b)` додає першим «Ввід a, b» (`funcblock`).
- **«Своя» функція vs бібліотечна.** `Call` (підпрограма) лише для функцій із
  `defined` (визначених у файлі). `print`/`input`/`range`/`len` — не підпрограми.
- **Обрізання тексту.** Будь-який текст у блок → один рядок, максимум 64 символи, далі
  «…» (`oneline`/MAXLEN).
- **f-рядки** показуються читабельно: `f"сума {x}"` → `сума {x}`.

## Межі

- Не моделюються: `match/case`, генератори/comprehension як керування, декоратори,
  async-керування, обробка конкретних `except`-гілок.
- `try/except` спрощено до тіла — діаграма показує «щасливий шлях».
