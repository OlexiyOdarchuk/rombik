# Diagram — модель геометрії

**Пакет:** `pkg/diagram` · **Файл:** `diagram.go`

Геометричний результат розкладки: фігури з координатами + ребра-стрілки + підпис. Це
**контракт** між [[Layout-рушій-розкладки|layout]] (виробляє) і **всіма рендерами**
([[SVG-рендерер|svg]], [[Typst-рендер|typst]], [[Растровий-рендер-PNG-PDF|raster]]).
Чиста структура даних, без логіки рендера.

## Kind — тип фігури

```go
type Kind int
const (
    Terminator Kind = iota // початок/кінець — овал (стадіон)
    Process                // дія — прямокутник
    Decision               // умова — ромб
    InOut                  // ввід/вивід — паралелограм
    Hexagon                // початок циклу (for) — шестикутник
    Predef                 // виклик підпрограми — прямокутник з рисками
)
```

- `Kind.String()` → машинна назва (`terminator`, `process`, `decision`, `io`, `loop`,
  `subprogram`).
- `MarshalJSON` віддає тип **рядком** у JSON.
- **`UnmarshalJSON`** приймає рядок («process») АБО число — щоб JSON, відданий
  фронтенду, розбирався **назад без втрат**. Це знадобилося, бо фронт шле `Diagram`
  у WASM назад для PNG/PDF і ре-рендеру підпису (round-trip). → [[WASM-міст]].

Зв'язок фігур із ДСТУ — [[ДСТУ-19.701-90]].

## Структури

```go
type Point struct { X, Y float64 }   // y росте ВНИЗ

type Shape struct {
    Kind Kind
    X, Y, W, H float64   // X,Y — лівий верхній кут; текст центрується
    Text string
}

type Edge struct {
    Points    []Point   // ортогональна ламана
    Label     string    // «Так»/«Ні»/«» (omitempty)
    Arrowless bool       // без вістря (для з'єднань у точці злиття)
}

type Diagram struct {
    Shapes    []Shape
    Edges     []Edge
    W, H      float64
    Caption   string  // підпис (за замовч. — ім'я функції; редагований)
    FigNum    int     // номер «Рисунок N» (0 — без номера)
    CapWord   string  // слово-supplement: «Рисунок»/«Рис.»/своє
    CapFormat string  // шаблон: «{word} {num} — {text}»
}
```

## Підпис «Рисунок N» (нове)

Поля підпису заповнює [[Публічний-API-rombik|rombik.build]]: `Caption` = ім'я
функції, `FigNum` = порядковий номер. Методи будують рядок підпису:

| Метод | Що повертає |
|-------|-------------|
| `CapSupplement()` | слово-supplement (`CapWord` або ДСТУ-замовч. «Рисунок») |
| `CapFmt()` | шаблон (`CapFormat` або «{word} {num} — {text}») |
| `CaptionLine()` | **повний рядок** «Рисунок 1 — grade» (для SVG/PNG/PDF, де нема авто-нумерації) |
| `CapSeparator()` | роздільник між номером і текстом (для нативної нумерації Typst-figure) |
| `CapHasWord()` | чи містить шаблон `{word}` |

Чому два шляхи: у **растрових** форматах (SVG/PNG/PDF) номер вшито в текст підпису
(`CaptionLine`), а в **Typst** нумерує сам `figure()`, тож йому потрібні лише слово й
роздільник. → [[Typst-рендер]].

## Чому `Arrowless`

Часто кілька ребер сходяться в одну точку (злиття гілок if, вхід у «Кінець»). Без
`Arrowless` був би «букет стрілок»; тому проміжні ребра без вістря, а голову дає лише
останнє. Деталі — [[Розкладка-if-guard-і-симетрія]], [[Розкладка-циклів]].

## Чому окрема пласка модель

- **Контракт для трьох рендерів.** Layout будує один `Diagram`, а svg/typst/raster
  читають його незалежно. Додати формат = новий читач, без змін розкладки.
- **Серіалізація + round-trip.** `Diagram` маршалиться в JSON (вихід `-o file.json`,
  поле `diagram` у відповіді WASM) і **розбирається назад** (`UnmarshalJSON`) для
  ре-рендеру.
- **Майже нуль залежностей** (лише stdlib) → імпортують усі, без циклів.

## Координатна система

(0,0) — лівий верхній кут; **y росте вниз**. Схема симетрична відносно осі `cx = W/2`.
Підпис малюється під схемою (запас `capGap` ≈ 30pt). Константи — [[Layout-рушій-розкладки]].
