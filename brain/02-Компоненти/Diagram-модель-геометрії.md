# Diagram — модель геометрії

**Модуль:** `diagram.ts` (`packages/engine/src/diagram.ts`)

Геометричний результат розкладки: фігури з координатами + ребра-стрілки + підпис. Це
**контракт** між [[Layout-рушій-розкладки|layout]] (виробляє) і **всіма рендерами**
([[SVG-рендерер|svg]], [[Typst-рендер|typst]], excalidraw). Чиста структура даних, без
логіки рендера. PNG/PDF теж читають цю модель — але вже у браузері
([[Растровий-рендер-PNG-PDF]]).

## Kind — тип фігури

```ts
export type Kind =
  | 'terminator' // початок/кінець — овал (стадіон)
  | 'process'    // дія — прямокутник
  | 'decision'   // умова — ромб
  | 'io'         // ввід/вивід — паралелограм
  | 'loop'       // початок циклу (for) — шестикутник
  | 'subprogram' // виклик підпрограми — прямокутник з рисками
  | 'connector'; // з'єднувач «А» — коло
```

`Kind` — **string union**: тип серіалізується рядком напряму (як у Go `MarshalJSON`),
тож JSON-round-trip (вихід `-o file.json`) розбирається назад без втрат — окремого
`UnmarshalJSON` не треба.

Зв'язок фігур із ДСТУ — [[ДСТУ-19.701-90]].

## Структури

```ts
export interface Point { x: number; y: number; }   // y росте ВНИЗ

export interface Shape {
  kind: Kind;
  x: number; y: number; w: number; h: number;       // x,y — лівий верхній кут; текст центрується
  text: string;
}

export interface Edge {
  points: Point[];        // ортогональна ламана
  label?: string;         // «Так»/«Ні»/«»
  arrowless?: boolean;    // без вістря (для з'єднань у точці злиття)
}

export interface Diagram {
  shapes: Shape[];
  edges: Edge[];
  w: number; h: number;
  caption?: string;       // підпис (за замовч. — ім'я функції; редагований)
  figNum?: number;        // номер «Рисунок N» (0/undefined — без номера)
  capWord?: string;       // слово-supplement: «Рисунок»/«Рис.»/своє
  capFormat?: string;     // шаблон: «{word} {num} — {text}»
}
```

## Підпис «Рисунок N»

Поля підпису заповнює [[Публічний-API-rombik|build.ts]]: `caption` = ім'я функції,
`figNum` = порядковий номер. Допоміжні **функції** (не методи) будують рядок підпису:

| Функція | Що повертає |
|---------|-------------|
| `capSupplement(d)` | слово-supplement (`capWord` або ДСТУ-замовч. «Рисунок») |
| `captionLine(d)` | **повний рядок** «Рисунок 1 — grade» (для SVG/PNG/PDF, де нема авто-нумерації) |
| `capSeparator(d)` | роздільник між номером і текстом (для нативної нумерації Typst-figure) |
| `capHasWord(d)` | чи містить шаблон `{word}` |
| `labelAnchor(p0, p1)` | позиція й вирівнювання підпису ребра (Так/Ні) за першим сегментом |

Константи: `CAPTION_WORD = 'Рисунок'`, `CAP_FORMAT_DEFAULT = '{word} {num} — {text}'`.

Чому два шляхи: у **растрових** форматах (SVG/PNG/PDF) номер вшито в текст підпису
(`captionLine`), а в **Typst** нумерує сам `figure()`, тож йому потрібні лише слово й
роздільник. → [[Typst-рендер]].

## Чому `arrowless`

Часто кілька ребер сходяться в одну точку (злиття гілок if, вхід у «Кінець»). Без
`arrowless` був би «букет стрілок»; тому проміжні ребра без вістря, а голову дає лише
останнє. Деталі — [[Розкладка-if-guard-і-симетрія]], [[Розкладка-циклів]].

## Чому окрема пласка модель

- **Контракт для всіх рендерів.** Layout будує один `Diagram`, а svg/typst/excalidraw
  (і браузерний PNG/PDF) читають його незалежно. Додати формат = новий читач, без змін
  розкладки.
- **Серіалізація + round-trip.** `Diagram` серіалізується в JSON (вихід `-o file.json`)
  і розбирається назад без втрат (string-`Kind`).
- **Нуль залежностей** → імпортують усі, без циклів і без DOM.

## Координатна система

(0,0) — лівий верхній кут; **y росте вниз**. Схема симетрична відносно осі `cx = w/2`.
Підпис малюється під схемою (запас ≈ 30pt). Константи — [[Layout-рушій-розкладки]].
