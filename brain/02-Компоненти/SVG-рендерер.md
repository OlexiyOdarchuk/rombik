# SVG-рендерер

**Пакет:** `pkg/render/svg` · **Файл:** `svg.go`

Малює [[Diagram-модель-геометрії|diagram.Diagram]] у SVG-рядок. Це **адаптер
виводу**: залежить лише від `diagram` (stdlib). Фігури — точні ДСТУ-примітиви, повний
контроль до пікселя.

> [!note] Один із трьох рендерів
> SVG — базовий. Поряд: [[Typst-рендер|typst]] (код CeTZ → PDF через Typst) і
> [[Растровий-рендер-PNG-PDF|raster]] (нативні PNG/PDF). Усі читають той самий
> `Diagram`. Растровий рендер навмисно повторює геометрію SVG координата-в-координату.

## Render — загальна структура

```go
func Render(d *diagram.Diagram) string
```

1. `<svg>` з `width/height/viewBox`, Arial 14px.
2. `<defs>` — маркер-стрілка `#arr` (трикутник `M0,0 L8,3 L0,6 Z`).
3. Білий фон `<rect>`.
4. **Спершу ребра** (під фігурами), **потім фігури** — щоб лінії не лізли поверх блоків.
5. `</svg>`.

Порядок «ребра → фігури» важливий: фігури перекривають кінці ліній, що входять у них.

## Ребра

Кожне ребро — `<path d="M.. L.. L..">` з `stroke-width=1.5`. Вістря —
`marker-end="url(#arr)"`, **крім** `Arrowless`-ребер (з'єднання в точках злиття; чому
так — [[Diagram-модель-геометрії]]).

### Розташування підпису (Так/Ні)

Мітку ставлять біля **початку** ребра (вершини ромба), а бік вибирають за напрямом
першого сегмента:

```
p1.X == p0.X  → вертикальний сегмент: підпис збоку, посередині висоти
p1.X <  p0.X  → ліворуч: text-anchor=end, текст назовні зліва
інакше        → праворуч: text-anchor=start
```

## Фігури — renderShape

Спільний стиль: `fill=#fdfdfd stroke=#222 stroke-width=1.5`.

| Kind | SVG | Геометрія |
|------|-----|-----------|
| `Terminator` | `<rect rx=H/2>` | овал-стадіон (заокруглення = піввисоти) |
| `Process` | `<rect>` | гострі кути |
| `Decision` | `<polygon>` 4 точки | ромб: верх-центр, право-центр, низ-центр, ліво-центр |
| `InOut` | `<polygon>` 4 точки | паралелограм, нахил `sk = 0.4·H` |
| `Hexagon` | `<polygon>` 6 точок | скоси з боків `sk = 0.5·H` |
| `Predef` | `<rect>` + 2 `<line>` | прямокутник + вертикальні риски на відступі 9pt |

Текст центрується в кожній фігурі: `text-anchor=middle dominant-baseline=middle` у
точці `(X+W/2, Y+H/2)`.

## Підпис «Рисунок N»

Якщо `d.CaptionLine()` непорожній, під схемою малюється підпис (запас `capGap`). Номер
тут вшито в текст (на відміну від Typst, де нумерує `figure`). → [[Diagram-модель-геометрії]].

## Допоміжне

- **`pathOf(pts)`** — будує `d`-атрибут: перша точка `M`, решта `L`.
- **`esc(s)`** — XML-екранування `& < > "` (бо текст блоку — довільний код користувача).

## Чому не Graphviz / svgo / d3

Потрібна **піксельна точність ДСТУ-фігур** (правильний шестикутник, правильний нахил
паралелограма) і повний контроль над підписами «Так/Ні». Власний рендер у ~100 рядків
це дає; зовнішня бібліотека — ні. До того ж нуль залежностей зберігає WASM-збірку
маленькою.
