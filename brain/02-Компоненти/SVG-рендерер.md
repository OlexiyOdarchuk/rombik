# SVG-рендерер

**Модуль:** `render/svg.ts` (`packages/engine/src/render/svg.ts`)

Малює [[Diagram-модель-геометрії|Diagram]] у SVG-рядок. Це **адаптер виводу**: залежить
лише від `diagram.ts` і `format.ts`, без DOM. Фігури — точні ДСТУ-примітиви, повний
контроль до пікселя.

> [!note] Один із рендерів рушія
> SVG — базовий. Поряд: [[Typst-рендер|typst]] (код CeTZ → PDF) і excalidraw
> (`render/excalidraw.ts`). Усі читають той самий `Diagram`. PNG/PDF більше не в
> рушії — це браузерний SVG→canvas ([[Растровий-рендер-PNG-PDF]]).

## API

```ts
export function render(d: Diagram): string        // один <svg>
export function renderAll(ds: Diagram[]): string  // усі схеми в ОДНОМУ SVG (вертикально)
```

(у [[Публічний-API-rombik|index.ts]] експортуються як `renderSvg`/`renderSvgAll`.)

## render — загальна структура

1. `<svg>` з `width/height/viewBox`, шрифт **Times New Roman** (serif fallback:
   Liberation Serif / DejaVu Serif), `font-size=14`.
2. `<defs>` — маркер-стрілка `#arr` (трикутник `M0,0 L8,3 L0,6 Z`).
3. **Спершу ребра** (під фігурами), **потім фігури** — щоб лінії не лізли поверх блоків.

Порядок «ребра → фігури» важливий: фігури перекривають кінці ліній, що входять у них.

## Ребра

Кожне ребро — `<path d="M.. L.. L..">` з `stroke-width=1.5`. Вістря —
`marker-end="url(#arr)"`, **крім** `arrowless`-ребер (з'єднання в точках злиття; чому
так — [[Diagram-модель-геометрії]]).

### Розташування підпису (Так/Ні)

Позицію й вирівнювання дає `labelAnchor(p0, p1)` з [[Diagram-модель-геометрії|diagram.ts]]
за напрямом першого сегмента:

```
горизонтальний сегмент → підпис над серединою (зсув обмежений ±34), text-anchor=middle
вертикальний сегмент   → підпис збоку (x+10), посередині висоти, text-anchor=start
інакше                 → праворуч-вгорі від початку
```

Підпис ребра малюється `font-size=12`, колір `#444`.

## Фігури — renderShape

Спільний стиль: `fill=#fdfdfd stroke=#222 stroke-width=1.5`.

| Kind | SVG | Геометрія |
|------|-----|-----------|
| `terminator` | `<rect rx=h/2>` | овал-стадіон (заокруглення = піввисоти) |
| `process` | `<rect>` | гострі кути |
| `decision` | `<polygon>` 4 точки | ромб: верх-центр, право-центр, низ-центр, ліво-центр |
| `io` | `<polygon>` 4 точки | паралелограм, нахил `sk = 0.4·h` |
| `loop` | `<polygon>` 6 точок | шестикутник, скоси з боків `sk = 0.5·h` |
| `subprogram` | `<rect>` + 2 `<line>` | прямокутник + вертикальні риски на відступі |

Текст центрується в кожній фігурі: `text-anchor=middle dominant-baseline=middle` у
точці `(x+w/2, y+h/2)`.

## Підпис «Рисунок N»

Якщо `captionLine(d)` непорожній, під схемою малюється підпис `font-size=14` (запас
`CAP_GAP=30`). Номер тут вшито в текст (на відміну від Typst, де нумерує `figure`). →
[[Diagram-модель-геометрії]].

## Допоміжне

- **`pathOf(pts)`** — будує `d`-атрибут: перша точка `M`, решта `L`. Координати через
  `f1` (одна десята) — Go-сумісне форматування з `format.ts`.
- **`esc(s)`** — XML-екранування `& < > "` (бо текст блоку — довільний код користувача).

## Чому власний рендер

Потрібна **піксельна точність ДСТУ-фігур** (правильний шестикутник, правильний нахил
паралелограма) і повний контроль над підписами «Так/Ні». Власний рендер у ~100 рядків
це дає; зовнішня бібліотека — ні. До того ж нуль залежностей тримає рушій легким і без DOM.
